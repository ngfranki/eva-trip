# 換暗號 · 操作指引（2026-09-16）

## 為什麼要換

| 現況 | 風險 |
|---|---|
| 旅程、飲食兩個 app 共用一個暗號，格式是「一個字＋年份」 | 被針對的人猜中的機會不是零 |
| 戰略中心（`wbh_board`）有公開網址 `ngfranki.github.io/wbh-center/`，裏面是廣告數據、學生名單、任務、情報 | 同樣只靠一個暗號 |
| 整個 Supabase project **沒有防暴力破解**（實測 20 次錯暗號 7 秒完成、零阻攔） | 可以無限次猜 |

已核實**不受影響**的東西：
- 戰略中心的 `board.py`、eva-oura 的 5 個腳本 → 用 service key，繞過暗號，照跑
- 飲食記錄 app（`meal_log`）→ 完全不碰，繼續用回舊暗號

## 先想好兩個新暗號

- 至少 12 個字，建議 16 個以上
- 兩個一定要**不同**（一個被猜中不會連累另一個）
- 例子格式：`四個無關英文字＋數字`，例如 `copper-lantern-quiet-42`
- 不要用：真名、生日、app 名字＋年份

**這兩個暗號我不會看到、不會經手，全部由你自己輸入。**

## 步驟一：加新暗號（舊的照用，不會斷線）

1. 開 https://supabase.com/dashboard/project/lvwspnjysfyomuszzjay/sql/new
2. 打開 `supabase/換暗號_步驟1.sql`，整份貼進去
3. **把最上面那兩行 `改我-…` 換成你自己的新暗號**（不改的話它會報錯，不會亂做）
4. 按 Run

做了什麼：只「加」3 條新 policy，完全不改不刪任何現有的。Postgres 的 policy 是 OR 關係，所以**新舊兩個暗號同時都通**。

會看到三段輸出：A（現況）、notice（✅ 三條已加）、B（加完之後）。
**把 A 段的內容貼回給我** —— 步驟二要根據它才寫得準。

## 步驟二：設定 AI／地圖的暗號

Edge function `trip-ai`（AI、Google 搜尋、路線）已經改好並部署了，現在**同時接受新舊暗號**。
已驗證：舊暗號 `meal2026` → 200 通；錯暗號 → 401 擋。

你要做的：加一個新 secret。
1. 開 https://supabase.com/dashboard/project/lvwspnjysfyomuszzjay/settings/functions
2. Add new secret：名 `TRIP_KEY`，值 = **你的旅程新暗號**（同步驟一那個一樣）
3. Save

🔴 **不要碰 `MEAL_KEY`** —— 它是飲食 app 的 `meal-vision` 共用的，改了會弄壞飲食 app。

## 步驟三：在裝置上換暗號

**旅程 app**（手機 ＋ Mac 各做一次）
1. 開 https://ngfranki.github.io/eva-trip/
2. 左邊欄 → 設定 → 清走暗號（或者在瀏覽器清走這個網站的資料）
3. 重新輸入**新的旅程暗號**
4. 確認：行程載得到、地圖有點、加地點搜尋有結果（這一步驗證 `TRIP_KEY` 設對了）

**戰略中心**（手機 ＋ Mac 各做一次）
1. 開 https://ngfranki.github.io/wbh-center/
2. 同樣清走舊暗號，輸入**新的戰略中心暗號**
3. 確認：看得到任務、廣告數據，改一樣東西看看存得到

## 步驟四：收緊（刪掉舊暗號）

確認兩個 app 在**手機和 Mac 都正常**之後，才做這一步。
我會根據步驟一 A 段的輸出寫 `換暗號_步驟2.sql` 給你。

做完之後：
- 舊暗號 `meal2026` 打不開旅程、打不開戰略中心
- 飲食 app 繼續用 `meal2026`，照用

---

## 如果中途出錯

步驟一到三**任何時候舊暗號都仍然有效**，所以不會出現「改完進不去」。
真的卡住：在 SQL Editor 執行
```sql
drop policy if exists trip_log_gate_v2 on public.trip_log;
drop policy if exists wbh_board_gate_v2 on public.wbh_board;
drop policy if exists trip_files_gate_v2 on storage.objects;
```
即刻回到原狀。

## 之後仍然存在的弱點（誠實講）

1. **service key** 一條鑰匙開全部（旅程、飲食、戰略中心），繞過所有暗號閘。已掃過：沒有洩漏，權限 600，不在任何 git repo、不在 iCloud、不在 shell history。它的安全 = 你部 Mac 的安全。
2. 換完暗號**仍然沒有防暴力破解** —— 只是把「猜得中」變成「幾乎猜不中」。Supabase 免費版沒有 rate limit，這個改不了。
3. 不是端對端加密：你的 Supabase 帳戶本身看得到全部資料。
4. 建議每月做一次「匯出 → JSON 全份備份」放自己的 iCloud —— 防誤刪、防惡意刪的唯一保險。
