# 換暗號 · 一步一步做

## 你需要準備

**兩個新暗號**，寫在紙上或記在 1Password：

- 至少 12 個字元
- 兩個一定要**不同**
- 例子格式：`copper-lantern-quiet-42`、`snowfield-teapot-88-north`
  （四個無關的英文字 ＋ 數字，好記又難猜）
- 不要用：你的名字、生日、`meal2026` 這種「字＋年份」

我不會看到這兩個暗號。由頭到尾都是你自己打進去。

我會叫它們：
- **暗號A** = 旅程 app 用
- **暗號B** = 戰略中心用

---

# 第 1 步：執行一段 SQL（大約 2 分鐘）

**這一步做什麼**：在資料庫裏面「多開一道門」，用你的新暗號。舊暗號那道門不動。
做完之後新舊兩個暗號都開得到 —— 所以不會斷線，隨時可以停手。

1. 用電腦開這個網址：
   `https://supabase.com/dashboard/project/lvwspnjysfyomuszzjay/sql/new`
   （會見到一個大的空白框，那是輸入 SQL 的地方）

2. 打開我給你的檔案 `換暗號_步驟1.sql`，**全選、複製**，貼進那個空白框

3. 在貼好的內容裏面，找這兩行（大約在中間，前面有 🔴）：

   ```
   new_trip  text := '改我-旅程新暗號';
   new_board text := '改我-戰略中心新暗號';
   ```

   把 `改我-旅程新暗號` 換成你的**暗號A**
   把 `改我-戰略中心新暗號` 換成你的**暗號B**

   ⚠️ 單引號 `'` 要留住，只換中間的字。改完應該像這樣：
   ```
   new_trip  text := 'copper-lantern-quiet-42';
   new_board text := 'snowfield-teapot-88-north';
   ```

4. 按右下角綠色的 **Run**（或者 ⌘ + Enter）

5. **你應該見到什麼**：下面會出現一個表格，還有幾行綠色字
   ```
   ✅ trip_log 已加新暗號閘
   ✅ wbh_board 已加新暗號閘
   ✅ storage trip-files 已加新暗號閘
   ── 新 policy 共 3 條（應該係 3）
   ```
   見到「共 3 條」就成功了。

   **如果見到紅色錯誤**：
   - 寫「仲未改暗號」→ 你忘了換那兩行，回去第 3 步
   - 寫「暗號太短」→ 打長一點，至少 12 個字元
   - 寫「兩個暗號一定要不同」→ 改其中一個

6. 把**最上面那個表格**（標題有 `A. 現有 policy`）整個複製，貼回給我。
   最後一步要看這個才寫得準。

---

# 第 2 步：加一個設定（大約 1 分鐘）

**這一步做什麼**：AI 功能和地圖搜尋不經資料庫，要另外告訴它新暗號。

1. 開這個網址：
   `https://supabase.com/dashboard/project/lvwspnjysfyomuszzjay/settings/functions`

2. 見到 **Edge Function Secrets** 那一段，按 **Add new secret**

3. 兩格這樣填：
   - Name：`TRIP_KEY`（一定要一模一樣，全大寫，中間是底線）
   - Value：你的**暗號A**

4. 按 **Save**

🔴 **列表裏面有一個叫 `MEAL_KEY` 的，千萬不要改它、不要刪它。**
那是飲食記錄 app 在用的，動了它飲食 app 就壞。

---

# 第 3 步：在手機和電腦輸入新暗號（每部機大約 1 分鐘）

## 旅程 app

在**手機**做一次，**Mac** 再做一次：

1. 開 `https://ngfranki.github.io/eva-trip/`
2. 按左上角 **☰**（三條線）
3. 拉到最底，按 **設定**
4. 按紅色的 **登出**
5. 畫面會回到暗號輸入格 → 輸入**暗號A** → 按「進入」
6. **確認這三樣**：
   - 行程載得出（見到北海道那個旅程）
   - 按「地圖」有見到地圖上的點
   - 在某一日的「加地點」打兩個字，有搜尋結果彈出來
     👉 第三樣最重要，它證明第 2 步的 `TRIP_KEY` 填對了

   如果搜尋沒有結果 → `TRIP_KEY` 打錯了，回第 2 步改。

## 戰略中心

**這個暫時不用做。** 它會在最後一步自己彈出來問你。

---

# 第 4 步：關掉舊暗號（等我）

你把第 1 步那個表格貼給我之後，我會寫最後一段 SQL 給你，做法和第 1 步一樣：
貼進去、按 Run。

執行完之後：
- 舊暗號 `meal2026` **打不開**旅程、**打不開**戰略中心
- 下次開戰略中心，它會自己彈出「暗號唔啱——再入一次」→ 你輸入**暗號B**
- 飲食記錄 app 繼續用 `meal2026`，完全不受影響

---

## 會不會弄壞其他東西？（已經逐個查過）

| 東西 | 會不會受影響 |
|---|---|
| 飲食記錄 app | ❌ 不會（完全不碰它） |
| 戰略中心的自動腳本（`board.py`） | ❌ 不會（用另一條鑰匙） |
| Oura 手環同步、自動早餐記錄（5 個腳本，每小時自動跑） | ❌ 不會（同上） |
| 你的旅程資料、附件 | ❌ 不會（只改門鎖，不碰裏面的東西） |

## 萬一卡住了

**第 1 到 3 步之間，舊暗號永遠仍然有效** —— 所以不會出現「改完進不去」。

真的想馬上回到原狀：在 SQL Editor 貼這三行，按 Run
```sql
drop policy if exists trip_log_gate_v2 on public.trip_log;
drop policy if exists wbh_board_gate_v2 on public.wbh_board;
drop policy if exists trip_files_gate_v2 on storage.objects;
```

**就算第 4 步之後打錯了暗號進不去，也鎖不死你** —— 你永遠有 SQL Editor，
重新執行第 1 步（用正確的暗號）就再開一道門。

## 做完之後仍然存在的弱點（誠實講）

1. **沒有防「不斷猜」的機制**。Supabase 免費版沒有這個功能，改不了。
   換暗號做的是把「有機會猜中」變成「幾乎猜不中」，不是加了一道鎖。
2. **`service key` 一條鑰匙開全部**（旅程、飲食、戰略中心），繞過所有暗號。
   已掃過：沒有洩漏，權限正確，不在任何 git、不在 iCloud、不在指令紀錄。
   它的安全 = 你部 Mac 的安全。
3. **不是端對端加密**：你的 Supabase 帳戶本身看得到全部資料。
4. **建議每月做一次**：旅程 app →「匯出」→「JSON 全份備份」→ 存自己的 iCloud。
   這是防誤刪、防被人刪的唯一保險。
